# Discover motion opportunities

## 1. Observe the seams

Walk the requested flow or inspect the supplied states. Look for missed acknowledgement, unexplained changes, lost identity, disorientation, and meaningful moments needing explanation. Include success, waiting, failure, cancellation, and repeated use. Use code searches to locate candidates, then examine their behavior or label the evidence as static.

**Complete when:** each candidate names a trigger, before/after state, and concrete communication gap or explicit hypothesis.

## 2. Filter before proposing

Apply the eligibility gate in [principles](../references/principles.md). Compare each candidate with a clearer static treatment. Assign one primary purpose. Use [patterns](../references/patterns.md) for the relevant component and [timing](../references/timing.md) when a numerical recipe is needed.

Keep instant navigation, readable data, and well-signaled state changes when they already serve the task. A conditional render, missing animation library wrapper, or immediate update is a candidate to inspect, not proof of a defect.

**Complete when:** every candidate has an add/keep/reduce/remove decision and reason, including rejected opportunities.

## 3. Deliver a shortlist

Use the opportunity contract in [outputs](../references/output-contracts.md). Return up to five high-value opportunities for a product, fewer for one view, unless broader coverage was requested. Rank communication/accessibility problems before expressive polish. Include precise proposed behavior and an equivalent reduced-motion state; label prototype values as provisional.

**Complete when:** each recommendation can become a design task without reconstructing the rationale; the report also states what should remain still and what evidence is missing.
